一、项目背景与目标
─────────────────────
以 i.MX6ULL-Pro 为核心，"Camera + 车载终端" 为场景，面向实习岗位的嵌入式
Linux 综合练兵项目。

我的策略（务实版）：
  • 不重复造轮子 — 内核中已有的复杂驱动 (V4L2、OV5640、USB Net) 直接使能使用。
  • 自己写简单模块 — GPIO 按键驱动、应用层采集/编码/上传逻辑，这些是面试常考
    且能体现能力的地方。
  • 系统已就绪 — 板子已有 Buildroot + Qt 可用，不做无谓的重构。
  • 目标不是"全自己写"，而是"能看懂、能调通、能扩展"。

================================================================================

二、硬件平台 — 韦东山 i.MX6ULL-Pro
────────────────────────────────────
关键特性：

  CPU: NXP i.MX6ULL, ARM Cortex-A7 @ 528MHz
  RAM: 512MB DDR3L（韦东山 Pro 版）
  Storage: 8GB eMMC + MicroSD 卡槽
  显示: 7" LCD (RGB565, 电容触摸)
  Camera: CSI 接口 (OV5640)
  网络: 100M Ethernet + AP6212 WiFi/BT (SDIO)
  4G: Mini-PCIe 接口 (EC200T 等)
  GPS: UART 接口 (NEO-6M / Ublox)
  USB: 1x OTG, 1x HOST
  UART: 调试串口 + 若干扩展
  SPI/I2C/GPIO: 丰富引出

确认的当前状态：
  ✅ 板子已烧录 Buildroot 系统
  ✅ 内核版本 4.9.88
  ✅ 系统自带 Qt 库
  ✅ 基础 BSP (U-Boot, kernel, dtb) 已就绪

七、学习路线与里程碑 (Roadmap)
─────────────────────────────────

Phase 0 — 环境摸底 (3 天)
  □ 确认板子当前系统状态: cat /proc/cpuinfo, uname -a, lsmod
  □ 确认摄像头设备: ls /dev/video*, v4l2-ctl --list-devices
  □ 确认 LCD Framebuffer: cat /sys/class/graphics/fb0/*
  □ 测试交叉编译: 写一个 hello.c，编译后 NFS 挂载运行
  □ Git 初始化项目仓库

Phase 1 — 内核配置与设备树 (1 周)
  □ 获取板子当前内核源码和 .config
  □ make menuconfig 使能 V4L2、OV5640、GPIO 输入、UART
  □ 修改设备树: 添加 GPIO 按键节点、确认 CSI/UART 节点正确
  □ 编译内核并烧录测试

Phase 2 — 按键驱动 (自己写!) + 应用层控制 (1 周)
  □ 编写 GPIO Input 子系统驱动 (misc device)
  □ 编写测试 app, 通过 input_event 读取按键
  □ 实现: 短按拍照、长按录像、双击退出

Phase 3 — 摄像头采集 (UVC + V4L2) (1~2 周)
  □ UVC 摄像头插入确认: lsusb, dmesg, ls /dev/video*
  □ V4L2 应用: 打开设备、设置格式、请求缓冲区、mmap、DQBUF
  □ 实现单帧捕获 → 存 JPEG 文件
  □ 实现连续采集 → 实时预览 (Framebuffer / Qt Widget)
  □ 帧率测试与优化

Phase 4 — 录像与存储 (自己写!) (1~2 周)
  □ MJPEG 逐帧写入文件，封装成 AVI
  □ 循环录像: 检测磁盘用量，自动删除最旧文件
  □ 按键控制录像启停

Phase 5 — GPS + 4G + MQTT (1~2 周)
  □ GPS 模块连接 & UART 测试: cat /dev/ttyX
  □ 集成 minmea 解析 NMEA → 得到经纬度/速度
  □ 4G 拨号 (ECM/PPP) → ifconfig 看到 usb0/ppp0
  □ MQTT 客户端: 连接 Broker，上报 GPS + 缩略图
  □ 内网用 Mosquitto 测试通过后，迁移到公网 Broker

Phase 6 — UI 整合 (1~2 周)
  □ 选择方案: Qt (现有) 或 LVGL (移植)
  □ UI 布局: GPS 信息、网络状态、录像状态、按键提示
  □ 所有功能联调，按键 → 采集 → 存储 → 上传 全链路打通
  □ 开机自启: Systemd service 或 inittab

Phase 7 — 面试准备 (贯穿始终)
  □ 整理项目用到的内核机制: platform bus、设备树、input subsystem、
    V4L2 ioctl、mmap、中断下半部
  □ 准备简历项目描述 (1 段 + 3 个要点)
  □ 模拟面试问答: "为什么选 MJPEG 而不是 H.264？"
    "共享内存和消息队列各自的优缺点？"
    "设备树是怎么匹配驱动的？"
  □ GitHub 仓库整理好 (README, 目录结构, 编译说明)

九、技术上的一些注意点
───────────────────────
  1. H.264 编码 → i.MX6ULL 无硬件编码器，x264 软编在 VGA 下可以跑，
     但如果卡顿，MJPEG 录像（只打包 JPEG 帧）是稳妥方案。
  2. 预览方案 → Qt 自带 Framebuffer 后端 (-qt-fb) 可以直接用，
     不需要折腾 DRM。先跑通，学有余力再研究 DRM/KMS。
  3. USB 摄像头 → 大多数支持 MJPEG 和 YUYV，优先 MJPEG 格式以降低 USB 带宽。
  4. GPS 模块 → 先用 USB 转串口在 PC 上验证 NMEA 数据格式，
     再连到板子 UART。
  5. 4G 模块 → 先内网测试 (以太网 + 本地 Mosquitto)，
     4G 拨号可以复用社区脚本。
  6. 驱动部分面试重点 → GPIO 按键驱动 (自己写的)、设备树、
     V4L2 ioctl 流程、platform_driver 匹配机制。
