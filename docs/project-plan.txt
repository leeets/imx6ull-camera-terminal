一、项目背景与目标
─────────────────────
以 i.MX6ULL-Pro 为核心，"Camera + 车载终端" 为场景，面向实习岗位的嵌入式
Linux 综合练兵项目。

我的策略（务实版）：
  • 不重复造轮子 — 内核中已有的复杂驱动 (V4L2、OV5640、USB Net) 直接使能使用。
  • 自己写简单模块 — GPIO 按键驱动、应用层采集/编码/上传逻辑，这些是面试常考
    且能体现能力的地方。
  • 系统已就绪 — 板子已有 Buildroot + Qt 可用，不做无谓的重构。
  • 目标不是"全自己写"，而是"能看懂、能调通、能扩展"。

二、硬件平台 — 韦东山 i.MX6ULL-Pro
────────────────────────────────────
关键特性：

  CPU: NXP i.MX6ULL, ARM Cortex-A7 @ 528MHz
  RAM: 512MB DDR3L（韦东山 Pro 版）
  Storage: 8GB eMMC + MicroSD 卡槽
  显示: 7" LCD (RGB565, 电容触摸)
  Camera: CSI 接口 (OV5640)
  网络: 100M Ethernet + AP6212 WiFi/BT (SDIO)
  4G: Mini-PCIe 接口 (EC200T 等)
  GPS: UART 接口 (NEO-6M / Ublox)
  USB: 1x OTG, 1x HOST
  UART: 调试串口 + 若干扩展
  SPI/I2C/GPIO: 丰富引出

确认的当前状态：
  ✅ 板子已烧录 Buildroot 系统
  ✅ 内核版本 4.9.88
  ✅ 系统自带 Qt 库
  ✅ 基础 BSP (U-Boot, kernel, dtb) 已就绪

五、"自己写" 与 "用现成" 的分界线
───────────────────────────────────
这是这个项目最重要的设计决策，直接决定你的实习面试能聊多深。

┌─────────────────────────────────────────────────────────────────────┐
│ 模块            │ 策略           │ 理由                             │
├──────────────────┼────────────────┼─────────────────────────────────┤
│ UVC 驱动         │ 用内核现成的   │ 内核已有完整驱动 (uvcvideo)       │
│ V4L2 框架        │ 理解并使用 API │ UVC + V4L2，应用层 ioctl 完全兼容  │
│ GPIO 按键驱动    │ 自己写！       │ 简单字符设备，面试必问             │
│ Camera 采集应用  │ 自己写！       │ hal_camera + capture 两层架构        │
│ 拍照存储         │ storage_manager │ 统一文件存储接口，接管拍照存盘       │
│ 录像             │ recorder        │ 调用 hal_camera 帧回调，逐帧打包 MJPEG │
│ 存储管理         │ storage_manager │ 文件写 + 循环覆盖 + 目录管理         │
│ GPS 解析         │ 用 minmea 库   │ 没必要重写 NMEA 解析器             │
│ 4G 拨号          │ 脚本集成       │ pppd/ecm 已有                     │
│ MQTT 上传        │ 用 paho 库     │ 标准库，学会使用即可               │
│ LVGL / Qt 显示   │ 集成现有库     │ 专注写业务逻辑，不造轮子            │
│ SQLite           │ 用现成库       │ 只调用 API                        │
│ 设备树节点       │ 自己改！       │ 面试常问，必须吃透                 │
└─────────────────────────────────────────────────────────────────────┘

策略总结：
  "看不懂的不写，但用到的必须能讲清楚原理。"
  自己写的是面试能展示的代码，用现成的是面试能展示的知识面。

九、技术上的一些注意点
───────────────────────
  1. H.264 编码 → i.MX6ULL 无硬件编码器，x264 软编在 VGA 下可以跑，
     但如果卡顿，MJPEG 录像（只打包 JPEG 帧）是稳妥方案。
  2. Framebuffer 预览 → hal_fb.c 轻量封装 /dev/fb0，直接 mmap 写显存。
     YUYV 转 RGB565 由 video_convert.c 完成，纯软件 0 依赖，VGA@15fps 可行。
  3. USB 摄像头 → 默认 YUYV 格式，避免 MJPEG 软件解码开销。
     如需拍照存 JPEG，用 libjpeg-turbo 在 storage_manager 中编码。
  4. GPS 模块 → 先用 USB 转串口在 PC 上验证 NMEA 数据格式，
     再连到板子 UART。
  5. 4G 模块 → 先内网测试 (以太网 + 本地 Mosquitto)，
     4G 拨号可以复用社区脚本。
  6. 驱动部分面试重点 → GPIO 按键驱动 (自己写的)、设备树、
     V4L2 ioctl 流程、platform_driver 匹配机制。
